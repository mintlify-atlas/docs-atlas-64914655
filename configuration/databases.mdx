CNEL Analytics uses a dual-database architecture. The **cloud SQL Server** database holds all CNEL EP historical electrical customer data and is accessed in a strictly read-only manner. The **local PostgreSQL** database stores application-level data — users, roles, permissions, and access logs — and is the only database the application writes to. Each database has its own SQLAlchemy engine and session factory, keeping the two concerns cleanly separated throughout the codebase.

## Cloud SQL Server database

The SQL Server instance hosts the CNEL EP historical data queried by the client information and reporting modules. The application opens only `SELECT` statements against this database; no writes or schema changes are ever made.

### Connection URL

Because SQL Server connections require an ODBC connection string with several driver parameters, `config.py` builds a URL dynamically using `urllib.parse.quote_plus` to percent-encode the entire ODBC string before embedding it in a SQLAlchemy URL:

```python backend/app/core/config.py
@property
def CLOUD_DATABASE_URL(self) -> str:
    odbc_str = (
        f"DRIVER={{{self.CLOUD_DB_DRIVER}}};"
        f"SERVER={self.CLOUD_DB_SERVER};"
        f"DATABASE={self.CLOUD_DB_NAME};"
        f"UID={self.CLOUD_DB_USER};"
        f"PWD={self.CLOUD_DB_PASSWORD};"
        "Encrypt=no;"
        "TrustServerCertificate=yes;"
    )
    return f"mssql+pyodbc:///?odbc_connect={quote_plus(odbc_str)}"
```

`Encrypt=no` and `TrustServerCertificate=yes` are set for compatibility with the CNEL EP network environment. Adjust these flags if your deployment uses TLS.

### ODBC driver prerequisite

The host machine must have **ODBC Driver 17 for SQL Server** installed (or whichever driver name is set in `CLOUD_DB_DRIVER`). On Ubuntu/Debian:

```bash
curl https://packages.microsoft.com/keys/microsoft.asc | sudo apt-key add -
sudo apt-get install -y msodbcsql17
```

On Windows, download the installer from the Microsoft Download Center and ensure the driver name registered in the ODBC Data Source Administrator matches the value in `CLOUD_DB_DRIVER`.

## Local PostgreSQL database

The PostgreSQL database is the application's own persistence layer. It stores everything needed to authenticate users and enforce role-based access control.

### Connection URL

The `LOCAL_DATABASE_URL` property uses the standard `postgresql+psycopg2://` scheme. Both the username and password are URL-encoded with `quote_plus` so that special characters in credentials do not break the URL:

```python backend/app/core/config.py
@property
def LOCAL_DATABASE_URL(self) -> str:
    user = quote_plus(self.LOCAL_DB_USER)
    password = quote_plus(self.LOCAL_DB_PASSWORD)
    return (
        f"postgresql+psycopg2://{user}:{password}"
        f"@{self.LOCAL_DB_HOST}:{self.LOCAL_DB_PORT}/{self.LOCAL_DB_NAME}"
    )
```

### Tables

| Table | Description |
|---|---|
| `usuarios` | Application user accounts (username, email, hashed password, active flag) |
| `roles` | Named roles assigned to users (e.g. `ADMIN`, `CONSULTA`) |
| `permisos` | Individual permission codes |
| `roles_permisos` | Many-to-many join between roles and permissions |
| `logs_acceso` | Audit log of login events and significant actions |

<Note>
  Passwords are stored as bcrypt hashes (via `passlib`). Plain-text passwords
  are never persisted. The `logs_acceso` table records each successful login
  with the user ID, action code `LOGIN`, and a timestamp generated by the
  database default.
</Note>

## SQLAlchemy session factories

`backend/app/db/session.py` creates two independent engines and two dependency-injectable session factories from the URLs built by `Settings`:

```python backend/app/db/session.py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from app.core.config import settings

# 1. Local PostgreSQL engine (users and roles)
engine_local = create_engine(settings.LOCAL_DATABASE_URL, pool_pre_ping=True)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine_local)

# 2. Cloud SQL Server engine (CNEL EP data)
engine_cloud = create_engine(settings.CLOUD_DATABASE_URL, pool_pre_ping=True)
SessionCloud = sessionmaker(autocommit=False, autoflush=False, bind=engine_cloud)

# FastAPI dependency — cloud session (client queries and exports)
def get_db():
    db = SessionCloud()
    try:
        yield db
    finally:
        db.close()

# FastAPI dependency — local session (auth and admin)
def get_local_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

Both engines use `pool_pre_ping=True`, which instructs SQLAlchemy to test each connection from the pool before using it. This silently recycles stale or dropped connections without surfacing errors to the user.

| Dependency | Engine | Used in |
|---|---|---|
| `get_db()` | `engine_cloud` (SQL Server) | `routers/clientes.py`, `routers/export.py` |
| `get_local_db()` | `engine_local` (PostgreSQL) | `routers/auth.py`, `routers/admin.py` |

## Verifying connectivity

**Python script** — `backend/test_db.py` tests that both engines can open a connection and execute a simple query. Run it before starting the application for the first time or after changing connection credentials:

```bash
cd backend && python test_db.py
```

**SQL Server Management Studio** — `backend/verify_client_fields.sql` checks that the columns expected by the application's query modules exist for a specific client code. Open the file in SSMS, replace `@codigo_cliente` with the client code you want to inspect, and execute it against the CNEL EP database.
